## 1. 2종 재화 구조 — 왜 하나가 아니라 둘인가

리서치 §1은 방치형 게임의 표준을 "소프트 커런시 + 세컨더리 + 프리미엄 + 프레스티지 메타"의
4계층으로 정리했다. 본 기획은 그중 **프리미엄(현금 재화)과 프레스티지 메타를 삭제**하고
**2계층만** 남긴다.

| 재화 | KO/EN | 용도 | 획득 | 게이트 |
|------|-------|------|------|--------|
| **CC** | 코어 크레딧 / Core Credits | **장비 티어 구매 전용** (채굴력 = 수익 경로) | 정산된 인양일수 기반 | **P1 게이트** |
| **SV** | 샐비지 / Salvage | **코스메틱 전용** (외장·도장·이펙트·명판) | 지층 상승·인가 완료·최초 달성 | 없음 |

### 1.1 재화를 두 개로 쪼갠 이유 (핵심 설계 판단)

단일 재화였다면 "예쁜 도장을 사면 장비 업그레이드가 늦어진다"는 트레이드오프가 생긴다.
장비는 실제 수익에 영향을 주므로, 그 트레이드오프는 **"코스메틱을 사면 돈을 덜 번다"** 는
구조가 된다. 이는 코스메틱 구매를 금전적 손해로 만들고, 반대로 코스메틱을 포기하도록 압박하는
강요적 설계다. 재화를 분리하면 이 압박이 **구조적으로 존재할 수 없다**.

부수 효과로, 컴플라이언스 경계선이 재화 이름 하나로 자명해진다:
> **CC가 관여하는 모든 것은 게이트 안, SV가 관여하는 모든 것은 게이트 밖.**

### 1.2 두 재화 공통 규칙 (하드 룰)

| # | 규칙 |
|---|------|
| C-1 | **현금·코인으로 구매 불가.** IAP 없음. 어떤 결제 경로도 재화로 연결되지 않는다 |
| C-2 | **사용자 간 이전·증여·거래 불가.** 2차 시장 없음. NFT 아님 |
| C-3 | **환전·출금·현금화 불가.** 금전적 가치 없음 |
| C-4 | **만료 없음.** 소멸 기한을 두지 않는다(소멸 기한 = 소비 압박 = 다크패턴) |
| C-5 | **차감은 사용자의 명시적 구매 행위로만 발생.** 패널티·수수료·자동 소모 없음 |
| C-6 | **확률형 사용처 없음.** 재화로 뽑기·상자·랜덤 결과물을 살 수 없다 |
| C-7 | **레퍼럴·초대·추천으로 획득 불가.** (아래 §2.3) |
| C-8 | **잔액과 전 거래 내역을 사용자가 언제든 열람 가능**(05 문서 §4 「기록」 탭) |

## 2. 획득 규칙

### 2.1 CC (코어 크레딧) — **P1 게이트**

XP와 동일한 소스에서, 동일한 상한으로 적립된다. 의도적으로 XP와 1:1로 붙였다 —
**성장 속도와 구매력을 같은 시계에 묶으면 밸런싱 변수가 하나로 줄고, 어느 한쪽만 폭주하는
상황이 발생하지 않는다.**

| 소스 ID | 조건 | CC | 상한 |
|---------|------|-----|------|
| `cc.lift` | `StakingPayout` 행 1개당 | 10 | 1 정산일당 최대 3포지션 → 일 30 |
| `cc.presence` | 정산일당 1회 방문(활성 포지션 ≥1) | 5 | 1일 1회. 연속 보너스 없음 |
| `cc.charter_open` | 신규 포지션 개설(승계 포지션 제외) | 40 | — |
| `cc.charter_complete` | 만기 도달 + `daysPaid >= termDays` | `min(300, 10 × termDays / 3)` | 90일 약정 = 300 |

기준선: 단일 포지션 **15 CC/일**, 3포지션 **35 CC/일** (최대 2.33배, 4번째 포지션부터 증가 없음).

### 2.2 SV (샐비지) — Phase 0

| 소스 ID | 조건 | SV |
|---------|------|-----|
| `sv.stratum` | 지층(챕터) 상승 시 1회 | 500 |
| `sv.charter_complete` | 인가(포지션) 만기 완주 시 | 50 |
| `sv.core_log` | 「심층 기록」 1단 상승마다(레벨 60 이후, 2,000 XP당) | 200 |
| `sv.first` | 최초 달성 기록 20종(최초 인양, 최초 T5 장비, 최초 지층 3 도달 등) | 종별 100 |

SV는 희소하고 이벤트성이다. **일일 적립이 없다** — 매일 접속해야 모이는 재화를 만들지 않기 위함.

### 2.3 획득 불가 소스 (명시적 배제 목록)

아래에서는 CC도 SV도 **절대** 나오지 않는다. 각각 이유가 다르므로 개별로 못 박는다.

| 배제 대상 | 이유 |
|-----------|------|
| **예치 금액(원금) 비례 적립** | 가격 피드가 없어 코인 간 비교 불가 + 보너스가 이미 이자(=원금)에 비례하므로 원금 이중 곱셈 + 증액 유도 업셀 구조(00 §4 Q2) |
| **레퍼럴 / 초대 / 하위 라인 실적** | 게임이 MLM 보상 플랜의 배수기가 된다. 리퍼럴 트리는 게임 데이터를 읽지도 쓰지도 않는다 |
| **입금·출금·거래·스왑 등 지갑 활동** | 게임화가 거래 빈도를 올린다는 FCA 정량 경고(거래 11~12% 증가)에 정면으로 해당 |
| **광고 시청 / 설문 / 외부 링크** | 다크패턴 및 제3자 데이터 이슈 |
| **클릭·탭·미니게임 등 클라이언트 조작** | 서버 검증 불가 = 위조 가능. P-5 위반 |
| **연속 출석 / 스트릭** | `docs/patterns/game-planner.md` 다크패턴 규칙 |
| **XP 부스터 아이템** | §5.3의 누출 분석 참조 — 간접적으로 수익 경로를 가속하므로 존재 자체를 금지 |

## 3. 보급창(Depot) — 상점 구조

상점은 두 개의 완전히 분리된 탭이다. 재화가 섞이지 않고, 상품이 섞이지 않는다.

```
보급창 / Depot
├── [정비] Maintenance   — CC 사용. 장비 5트랙 × 10티어. 영구·확정·수익 영향 O   ← P1 게이트
└── [외장] Outfitting    — SV 사용. 코스메틱. 영구·확정·수익 영향 X            ← Phase 0
```

### 3.1 상점 하드 룰

| # | 규칙 | 근거 |
|---|------|------|
| S-1 | **모든 상품은 확정형.** 가격 ↔ 효과가 상품 카드에 고정 표기. 랜덤 없음 | 리서치 §5 루트박스 규제 |
| S-2 | **한정 판매·타이머·카운트다운·"곧 마감" 없음** | FOMO 금지(A4) |
| S-3 | **할인·번들·"n개 사면 1개" 없음** | 구매량 유도 금지 |
| S-4 | **구매 확인 다이얼로그 필수.** 잔액·차감액·구매 후 잔액·효과를 모두 표기 | 오구매 방지 |
| S-5 | **환불 없음, 되팔기 없음** — 그리고 이 사실을 확인 다이얼로그에 명시 | |
| S-6 | 구매 성공 시 **연출은 정보 표시 수준.** 폭죽·팡파레·희귀도 연출 금지 | A5, 리서치 §5 "축하 메시지" 우려 |
| S-7 | 재화가 부족할 때 **"충전" 유도 경로가 존재하지 않는다** (충전 자체가 없으므로) | C-1 |
| S-8 | 상품 목록은 **서버가 소유**한다. 클라이언트는 상품 ID만 전송, 가격·효과는 서버 조회 | 위조 방지 |

## 4. 정비 탭 — 장비 트랙 (**P1 게이트**)

> 이하 §4~§6은 `pm` 사인오프 전까지 **제안**이다. 구현 착수 금지.

### 4.1 구조

5개 트랙(01 문서 §5) × 10티어. 각 티어는 **한 번만** 구매 가능하며 순차적이다(T3을 사려면 T2 필요).

### 4.2 티어 가격표 (CC) 및 채굴력(MP)

**모든 티어의 MP 효과는 동일하게 +4 MP다.** 가격만 오른다.

| 티어 | CC 가격 | +MP | 누적 CC(1트랙) | CC/MP 효율 | 레벨 요건 |
|------|---------|-----|----------------|------------|-----------|
| T1 | 15 | +4 | 15 | 3.8 | 트랙 개방 레벨 |
| T2 | 30 | +4 | 45 | 7.5 | — |
| T3 | 50 | +4 | 95 | 12.5 | — |
| T4 | 80 | +4 | 175 | 20.0 | 15 |
| T5 | 120 | +4 | 295 | 30.0 | — |
| T6 | 170 | +4 | 465 | 42.5 | 25 |
| T7 | 230 | +4 | 695 | 57.5 | 35 |
| T8 | 300 | +4 | 995 | 75.0 | 45 |
| T9 | 380 | +4 | 1,375 | 95.0 | 55 |
| T10 | 475 | +4 | 1,850 | 118.8 | **60** |

- 1트랙 완주 = **1,850 CC**, 5트랙 전체 = **9,250 CC**.
- 트랙 개방 레벨: `drill`·`power` L5, `mud` L12, `cool` L22, `auto` L32 (02 문서 §4.2).

### 4.3 밸런싱 근거

**(a) 효과는 정액, 가격은 체증 — 곱연산을 쓰지 않은 이유.**
리서치 §3은 "매니저류 속도 부스트를 배율형 업그레이드 위에 얹으면 곱연산으로 수익률이 급격히
증가"하며 "후반 인플레이션이 심해질 수 있다"고 경고했다. 실제 자금이 걸린 시스템에서 이 인플레이션은
곧 **플랫폼 채무의 지수적 증가**다. 따라서 본 설계는 어디에서도 곱연산을 쓰지 않는다:

> **MP는 전부 덧셈이다. MP → 보너스 변환도 선형이며, 그 위에 하드 캡이 있다.**
> 레벨 MP + 장비 MP, 그 이상은 없다. 배수 아이템도, 배수 이벤트도, 배수 스택도 없다.

정액 효과 + 체증 가격은 **자동으로 수확 체감**을 만든다(T1은 3.8 CC/MP, T10은 118.8 CC/MP —
약 31배 비효율). 별도의 감쇠 규칙 없이 "초반은 빠르게, 후반은 느리게"가 성립한다.

**(b) 총 비용을 최대 레벨 도달 시점에 맞춘 이유.**
5트랙 완주 9,250 CC ÷ 15 CC/일 ≈ **617일**. 최대 레벨 도달 647일(02 문서 §3.4)과 거의 일치한다.
따라서 **최대 채굴력(레벨 60 + 전 트랙 T10)은 약 650일 시점에 동시에 도달**한다.
의도적 정렬이다 — 어느 한쪽만 먼저 최대치가 되면 나머지 기간 동안 그 트랙의 성장 피드백이
죽는다. 그리고 이 정렬 덕분에 "**최대 보너스는 자금이 아니라 약 2년의 시간으로 도달한다**"는
문장이 두 축 모두에서 참이 된다(A8).

**(c) 3포지션 사용자는 2.33배 빠르지만 최대치는 같다.**
3포지션 사용자는 약 265일에 5트랙을 완주한다. 그러나 T10은 레벨 60이 요구되고, 레벨 60은
277일이 필요하다 — **레벨이 항상 병목**이다. 즉 포지션을 늘려도 최대 보너스 도달 시점을
277일 미만으로 당길 수 없다. 이것이 자금력의 이점에 걸린 천장이다.

**(d) 병목 유도(시각 신호만).**
5트랙 중 최저 티어 트랙이 리그 위에서 낡아 보이게 표현한다(01 문서 §5). **수치 페널티는 없다.**
Idle Miner Tycoon식 병목 튜토리얼 동선(리서치 §3)의 순화 버전 — 어디에 쓸지 알려주되,
잘못 쓴 것을 벌하지 않는다.

### 4.4 채굴력(MP) 산출

```
MP_level = 5 × level                       // L1 = 5,  L60 = 300
MP_gear  = 4 × (모든 트랙의 보유 티어 합)   // 최대 4 × 50 = 200
MP       = MP_level + MP_gear              // 최소 5, 최대 500
```

| 구간 | MP | 최대치 대비 |
|------|-----|-------------|
| 신규(L1, 장비 없음) | 5 | 1.0% |
| L30, 3트랙 T6 | 150 + 72 = 222 | 44.4% |
| L60, 장비 없음 | 300 | 60.0% |
| L1, 전 장비(불가능 — 레벨 요건) | — | — |
| **L60 + 전 트랙 T10** | **500** | **100%** |

**레벨이 MP의 60%를 차지한다.** 즉 채굴력의 과반은 **살 수 없는 것**이며, 나머지 40%를 사는
데 쓰는 CC조차 예치 일수에서만 나온다. 어느 경로로도 "돈을 더 넣어서 즉시 최대치"가 불가능하다.

## 5. 외장 탭 — 코스메틱 (Phase 0)

### 5.1 슬롯

| 슬롯 | 개방 레벨 | 내용 |
|------|-----------|------|
| 크루 헬멧 | 8 | 크루 5인 공통 헬멧 디자인 |
| 리그 도장 | 18 | 리그 전체 컬러 스킴 |
| 지층 조명 프리셋 | 28 | 배경 조명 톤 변경 |
| 드론 스킨 | 38 | K-9 외장 |
| 배경 이펙트 | 48 | 파티클·대기 효과 |
| 리그 명판 | 60 | 리그에 새겨지는 각인 |

### 5.2 가격대 (SV)

| 등급 | 가격 | 비고 |
|------|------|------|
| 기본 변형 | 200 SV | 색 변경 수준 |
| 표준 | 500 SV | 형태 변화 포함 |
| 지층 한정(해당 지층 도달 시 상시 판매) | 800 SV | "한정"은 **시간 한정이 아니라 진행도 한정**. 도달하면 영구히 구매 가능 |
| 심층 기록 보상 | 1,200 SV | 레벨 60 이후 트랙 |

**"한정"의 의미를 시간이 아니라 진행도로 정의한 것은 의도적이다**(S-2). 놓칠 수 있는 상품을
만들지 않는다.

### 5.3 XP 부스터·소모품을 만들지 않는 이유 (누출 분석)

방치형 상점의 표준 품목인 "XP 2배 3일권"류를 **금지**한다. 경로를 따라가면 이유가 자명하다:

```
XP 부스터 구매 → 레벨 상승 가속 → MP_level 증가 가속 → 보너스율 증가 가속 → 실제 지급액 증가
```

즉 XP 부스터는 **이름만 게임 아이템이고 실제로는 수익률 가속 아이템**이다. 시간 제한이 붙는
순간 A4(수익 경로에 긴급성 장치 금지)까지 함께 깨진다. 같은 논리로 다음도 전부 금지한다:

- XP·CC 획득량 증가 아이템 (일시적이든 영구든)
- 정산 결과를 미리 보거나 앞당기는 아이템
- 상한(3포지션 캡, 일 30 CC 캡)을 늘려 주는 아이템
- 「심층 기록」 진행을 가속하는 아이템

**소모품(만료되는 아이템)은 카테고리 자체를 만들지 않는다.** 상점의 모든 상품은 영구다.

## 6. 데이터 모델 & 구매 흐름 (**P1은 게이트**)

```
GameGear
  userId  String
  track   String   // 'drill' | 'mud' | 'cool' | 'power' | 'auto'
  tier    Int      @default(0)   // 0 = 미보유, 최대 10
  @@id([userId, track])
```

```
GameLedgerEntry                       // CC/SV 통합 append-only 원장
  id, userId, currency ('CC'|'SV'), delta Int, reason String,
  refId String, balanceAfter Int, dayKey String, createdAt
  @@unique([userId, currency, reason, refId])   // 멱등
  @@index([userId, createdAt])
```

### 6.1 구매 트랜잭션 규칙

1. 클라이언트는 `{ track, targetTier }` 또는 `{ cosmeticId }` 만 보낸다. **가격을 보내지 않는다.**
2. 서버는 `requireUser()`로 사용자를 확정하고, 서버 상수 가격표에서 가격을 조회한다.
3. 단일 DB 트랜잭션 안에서: 레벨 요건 검증 → 선행 티어 검증 → 잔액 검증 → 차감 → 티어 기록 →
   원장 행 기록. 하나라도 실패하면 전부 롤백.
4. **효과 발생 시점은 다음 정산일부터**(A9). 응답에도 그렇게 명시한다.
5. 동일 요청 재전송(더블 클릭·네트워크 재시도)은 `@@unique`와 선행 티어 검증에 의해 무해하다.

### 6.2 오류 코드 (05 문서 §6에서 카피 매핑)

| 코드 | 조건 |
|------|------|
| `DEPOT_INSUFFICIENT_BALANCE` | 잔액 부족 |
| `DEPOT_LEVEL_REQUIRED` | 레벨 요건 미달 |
| `DEPOT_TIER_SEQUENCE` | 선행 티어 미보유 |
| `DEPOT_ALREADY_OWNED` | 이미 보유 |
| `DEPOT_ITEM_UNKNOWN` | 알 수 없는 상품 ID |
| `DEPOT_DISABLED` | 상점 비활성(관할 킬 스위치 또는 점검) |

## 7. 수용 기준 (AC)

| ID | 기준 |
|----|------|
| AC-D1 | CC와 SV는 어떤 경로로도 상호 교환되지 않는다 |
| AC-D2 | 상점에 랜덤 결과물을 반환하는 상품이 하나도 없다 |
| AC-D3 | 상품 가격이 클라이언트 요청 본문에서 읽히는 코드 경로가 없다 |
| AC-D4 | 재화 잔액을 증가시키는 API 엔드포인트가 없다(적립은 서버 내부 이벤트에서만) |
| AC-D5 | 만료 타임스탬프를 가진 아이템이 하나도 없다 |
| AC-D6 | 구매 직후 조회한 보너스율이 구매 전과 동일하다(다음 정산일부터 반영, A9) |
| AC-D7 | 원금(`principal`)을 읽어 재화를 적립하는 코드가 없다 |
| AC-D8 | 레퍼럴 관련 테이블을 읽어 재화를 적립하는 코드가 없다 |
| AC-D9 | MP 산출 경로에 곱셈이 한 번도 나타나지 않는다(계수 곱 제외, 스택 곱 없음) |
| AC-D10 | 레벨 요건을 만족하지 않은 티어를 구매하려는 요청이 서버에서 거부된다 |
