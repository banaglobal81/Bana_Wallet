# DEEP CORE — 기획서 08: Phase 0 자산 배치 1 — 산출물 목록 & 인계

## 1. 자산 위치

```
web/public/game/deep-core/
├─ manifest.json              ← 기계 판독용 목록(id·경로·해상도·투명 여부·챕터·용도)
├─ backgrounds/                6장 (챕터 1·2 패럴랙스 sky/mid/fore)
├─ rig/                        1장 (리그 베이스 실루엣, 챕터 1)
├─ wells/                      2장 (시추정 소/대, 챕터 1)
├─ props/                      2장 (필드 프롭)
├─ characters/portraits/       6장 (크루 5인 + 감사관)
├─ characters/sprites/         2장 (전신 idle 포즈 샘플)
├─ icons/                      3장 (SV·XP·총 가동일)
├─ icons/tabs/                 4장 (리그·크루·보급창·기록)
├─ badges/                     3장 (지층·레벨·심층 기록 배지 샘플)
├─ cosmetics/                  2장 (헬멧·리그 도장 샘플)
└─ fx/                         2장 (파티클 아틀라스, 인양 버스트)
```

`web/public/` 하위이므로 Next.js가 빌드 시점 정적 자산으로 그대로 서빙한다 — 추가 API 라우트나
R2 프록시 코드가 필요 없다. `game-developer`는 Phaser 로더에 `/game/deep-core/...` 절대 경로를
그대로 쓰면 된다. **이 경로 선택 이유**: 05 문서 G-3이 게임 코드 트리를
`web/src/components/staking/deep-core/`로 못박았으므로, 정적 자산도 `deep-core` 이름을 공유해
같은 트리로 인식되게 했다. 자산은 `src` 트리 밖(코드 아님)이라 G-3(코드 격리) 대상은 아니지만,
되돌리기 시 `web/public/game/deep-core/` 디렉터리 하나만 지우면 된다는 점은 동일한 격리 이점이다.

## 3. Phase 0 스코프 준수 확인

07 문서 §0의 배제 규칙을 그대로 지켰다 — 이번 배치에 **다음은 한 장도 없다**: 장비 트랙 파츠
(드릴/이수/냉각/동력/자동화, B1), 보급창 티어 썸네일(B3), 병목 오버레이(B4), CC 아이콘, MP
아이콘, 트랙 아이콘(E3), 티어 배지(E4). `dc_rig_base_ch1` 1장만 "장비"류로 보일 수 있으나, 이는
`rig_silhouette` 언락(레벨/챕터 기반, 수익 영향 없음)이며 `gear_tier_cap`(CC 구매, P1 게이트)과는
분리된 항목이다 — 07 문서 §0 표 참조.

## 4. 알려진 이슈 및 수정 이력

생성 과정에서 스타일 락 프롬프트에 특정 게임 타이틀명("Hay Day", "Township")을 스타일 참조로
넣었더니, 모델이 이를 문자 그대로 받아들여 관련 없는 농장/풍차 장면을 그리는 **콘텐츠 누출**이
5장에서 발생했다(`dc_bg_ch2_sky`, `dc_bg_ch1_fore`, `dc_bg_ch1_mid`, `dc_icon_xp`,
`dc_fx_lift_burst_ch1`). 스타일 락 문구에서 게임 타이틀명을 전부 제거하고 형용사 서술("bold clean
silhouettes, flat cel-shading" 등)로 대체 + 명시적 금지 목록(농장·풍차·헛간·동물·무관 캐릭터)을
추가한 뒤 재생성해 전부 해결했다(`dc_icon_xp`는 지갑 일러스트가 섞여 나와 한 번 더 재생성).
**교훈**: 스타일 참조는 절대 특정 작품명으로 주지 말 것 — `docs/patterns/game-designer.md`에 기록.

`dc_bg_ch1_mid`도 최초 생성에서 배경에 실제 "도시 스카이라인"(고층빌딩 실루엣)이 등장해
W-7(실존 요소 암시 금지) 취지에 어긋나 재생성했다 — 최종본은 원경에 다른 시추 리그들만 보인다.

## 5. 매팅(투명 PNG) 관련 한계

07 문서 §7에 기록된 대로, 파이프라인이 진짜 알파 투명 PNG를 직접 뱉지 못해 마젠타 배경 +
자체 제작 크로마키 스크립트(코너 픽셀 자동 샘플링 + 거리 임계값 + 페더)로 후처리했다. 딥 네이비
(`#06132a`) 배경에 합성해 육안 검수한 결과 전반적으로 깨끗하지만, 일부 초상화의 모자·턱선
가장자리에 옅은 마젠타 헤일로가 남아 있다(예: `dc_crew_boss_portrait_ch1`). **프로덕션 마무리
전 권장**: 포토샵/GIMP 등에서 해당 가장자리 수동 정리, 또는 전문 매팅 도구(`rembg` 등) 재적용.
치명적 결함은 아니며 Phase 0 데모/스테이징 용도로는 그대로 사용 가능하다.

## 6. 후속 배치 백로그 (06 문서 P0 세트 잔여분, 우선순위 순)

이번 배치는 "히어로 세트"로 스타일을 확립하고 즉시 화면에 꽂을 수 있는 최소 세트를 만든 것이며,
06 문서 §4의 P0 파도(85장) 전체를 다 채우지 못했다. Vertex AI 공유 쿼터(2 req/분)상 대량 생성은
여러 세션에 걸쳐야 한다. 다음 배치 시 우선순위:

1. **크루 액션 시트(A1)** — 이번 배치는 idle 포즈 2장만 만들었다. `working`/`waiting`/
   `idle_empty`/`chapter_up` 5개 상태 × 5인 크루의 실제 스프라이트시트 애니메이션 프레임은
   미제작. 06 문서 A1(26장)이 대상. 이 파이프라인은 시드 고정이 없어 프레임 간 일관성 확보가
   어려우므로, `game-developer`와 협의해 프레임 수·방식(생성 vs 수작업 리깅)을 재확인할 것.
2. **크루 5인의 챕터별 나머지 초상**(A2 잔여 20장) — 이번 배치는 챕터당 1벌만 만들었다.
3. **패럴랙스 챕터 3~6**(C1 12장) — 이번 배치는 챕터 1·2만.
4. **시추정 크기·챕터 조합 잔여**(D1 24장), **필드 프롭 잔여**(D2 46장).
5. **광폭 캔버스 확장** — 06 문서가 요구하는 1920×540(sky/mid) 규격은 이 파이프라인이 직접
   지원하는 종횡비가 아니라(포맷 검증만 하고 값 검증은 API가 함) 전부 16:9로 생성했다. 좌우
   스크롤 여유가 필요하면 아웃페인팅/타일링 후속 작업 필요.
6. 나머지는 06 문서 §4 P1/P2 파도 순서를 따른다.

## 7. `game-developer` 인계 메모

- `manifest.json`을 코드에서 직접 import/fetch해 자산 경로를 하드코딩하지 않는 것을 권장.
- 배경(`dc_bg_*`)만 불투명, 나머지는 전부 알파 투명 PNG.
- 최종 배포 전 WebP 변환 및 06 문서 §5(챕터 아틀라스, ≤900KB/챕터) 규칙에 맞춘 압축·리사이즈
  필요 — 현재 파일은 원본 생성 해상도(1024×1024 등)이며 아직 아틀라스로 패킹되지 않았다.
- `dc_rig_base_ch1`을 CC/장비 트랙 UI와 절대 같은 화면 동선에 놓지 말 것(07 문서 §0) — 리그
  베이스는 항상 "레벨업으로 자동 갱신"되는 자산으로만 노출한다.
