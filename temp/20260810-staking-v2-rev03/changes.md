## 왜

개정 02 이후 아래 4종의 새 입력이 도착했고, 그 중 3개가 개정 02의 판정 전제를 직접 바꾼다.

1. **마스터 Q-M1 답변** — "Nia-Hub에도 BANA가 등록되어 있을 수 있음."
   개정 02의 모델 (C)가 안전한 **유일한 근거**였던 배타성(X-1)을 마스터가 보장하지 않았다.
   → 배타성 불변식의 정의 자체를 다시 써야 한다("등록 금지"가 아니라 "잔고 보유 venue 단일").
2. **마스터 Q-M2 답변** — 출금은 수동 실행(pm 권고 수용).
   → B-7 종결. 핫월렛 PRD 선행 요구가 사라진다. 최상위 차단 항목 하나 해제.
3. **마스터 Q-M4 답변** — BANA 외부 입금 지원 필요.
   → B-9가 "정책 질문"에서 "설계 과제"로 전환. 그리고 Q-M1과 상호작용한다(허브 입금을 쓰려면
     권위가 허브로 가야 함 — 두 설계는 가산적이지 않다).
4. **마스터 신규 지침** — "게임 기획 전 기존 스테이킹 시스템은 모두 삭제, v2와 동시 교체."
   + 프로덕션 실측(StakePosition 0 / StakingPayout 0 / WithdrawalRequest 0).
   → 개정 01 §5(전환 전략·밴드폭 0 승계·메타데이터 백필)가 **불필요**해진다. §1.1(기존 부채
     전액 인정)도 대상 부채가 0이라 사실상 공전.

추가로 긴급 위험 2건의 실측 결과가 도착했다(RISK-1 차단 완료 / RISK-2 결함 실재·미트리거).

## 어떻게 바뀌는가 (요지)

- 배타성 요구 X-1 → **X-1′(잔고 보유 venue 단일)** 로 재정의. X-3 → 2단계 감지(경고/차단).
- 클레임 레일이 **외부 호출에서 내부 DB 트랜잭션**으로 축소 → 개정 01 C-3/C-4/C-10/C-11 재범위.
- 출금 승인 큐가 **권위 분기 지점**이 된다. 실행 단계만 분기(허브 forward vs 온체인 수동 + 해시 검증).
- 게이트: G-0‴ → **G-0⁗**, G-1′ → **G-1‴**(엔드투엔드 증명으로 강화).
- 프로그램을 **V2-CORE / V2-BAND** 로 분할 — 법무(H-3)·재원(H-4)은 V2-BAND만 막는다.
- §14 전면 갱신 — 마이그레이션·백필 작업 항목 삭제, 착수 가능 항목 명시.
