# 변경 사항 — 관리자 크레딧 4-eyes 판정 (AC-8 재개 조건 도달)

## 왜 (Why)

`prisma-db-expert`의 T-2/CS-2′ 프로덕션 재조회(2026-08-11)에서 `User(role='ADMIN')` = **2건**이
확인됐다. rev05 §4A.4 **요구 AC-8**은 *"재개 조건(무조건): 관리자 계정이 2개 이상이 되는 시점에
4-eyes를 필수로 전환한다"* 고 못 박았다. **그 조건이 충족됐다.**

AC-8이 이번 라운드 미구현을 정당화한 근거는 *"관리자가 사실상 1인인 동안 2인 승인은 계정 공유로
우회되어 감사 추적만 오염된다"* 였다. 계정이 2개가 된 순간 **그 근거 자체가 사라진다** — 즉
미구현 판정을 지탱하던 전제가 없어졌으므로, 판정도 함께 만료된다.

동시에 판단해야 할 것은 **긴급도**다. 관리자 크레딧 표면은 코드가 완성·커밋됐지만
`adminCreditEnabled` 킬 스위치가 꺼진 상태이고, 프로덕션은 해당 컬럼을 만드는 마이그레이션 2건이
아직 미적용이다(CS-2′ §4). 즉 **현재 프로덕션에는 발행 능력이 존재하지 않는다.**
"조건이 충족됐다"와 "지금 당장 무언가를 해야 한다"는 다른 명제이며, 이 문서가 그 둘을 분리한다.

## 무엇을 (What)

`docs/specs/staking-yield-system-v2-prd-rev05b-four-eyes-ruling.md` 신규 작성 — rulings 형식.

1. **AC-8 발동 확인** — 조건은 무조건적이고 이미 충족됐다.
2. **긴급도 판정** — 지금 당장의 블로킹 이슈가 **아니다.** 요구가 걸리는 대상은
   *배포된 코드*가 아니라 **킬 스위치를 켜는 행위**다.
3. **AC-18(신설)** — 킬 스위치 ON 게이트 G-1.
4. **AC-19(신설)** — 4-eyes 요구의 형태(제안/승인 분리, 실행 시점 한도 검사, 만료, 감사 5종,
   크레딧 전용).
5. **AC-20(신설 · 금지)** — 4-eyes 구현 전까지 킬 스위치를 관리자 UI/API에서 토글 가능하게
   만들지 않는다(현재 DB 직접 쓰기로만 가능한 상태가 사실상의 게이트이므로).
6. **신규 트랙 T-20~T-24 배정** — T-16/T-17/T-18 재작업이 아니라 확장. T-20(FRD, `product-planner`)
   필요하다고 판정.
7. **미해결 27 종결 + 신규 미해결 등재.**

## 코드 영향 (이 문서가 유발하는 것)

이 세션에서 코드는 0줄 변경한다(`pm` 경계). 다만 이 판정은 향후 아래를 유발한다 —
- `prisma-db-expert`: `AdminCreditProposal` 스키마 + 마이그레이션 (T-21)
- `web-shared-expert`: 제안/승인/거절/만료 라우트 + 실행 경로 수정 (T-22, 기존 T-17 산출물 확장)
- `web-admin-expert`: 8번째 상태 + 승인 인박스 + 6로케일 (T-23, 기존 T-18 산출물 확장)
- `wallet-security-expert`: 보안 리뷰 = 스위치 ON 게이트 (T-24)

**착수 시점은 이 문서가 지정하지 않는다** — CUT-4 내부 E2E가 크레딧에 의존하므로 임계경로에
들어온다는 사실만 명시하고, 우선순위는 마스터 결정 사항으로 남긴다.

## 이 변경이 승인하지 않는 것

- CUT-2b 배포 승인 아님(AC-14 = T-19 보안 리뷰 게이트 그대로).
- 킬 스위치 ON 승인 아님.
- 프로덕션 마이그레이션 2건 적용을 **막지 않는다**(컬럼 추가만으로는 발행 능력이 생기지 않음).
- 한도 3종 초기값(Q-M10) 확정 아님.
- AC-1~AC-17 중 어느 것의 완화도 아님.
