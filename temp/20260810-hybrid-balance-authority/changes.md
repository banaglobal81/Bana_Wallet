# changes — 하이브리드 잔고 권위(코인별 분할) 판정

날짜: 2026-08-10 · 담당: `pm`

## 무엇이 바뀌는가

마스터가 B-0(사용자 잔고의 권위)에 대해 **(A) 허브 / (B) BANA DB 택일이 아니라
코인별 분할**로 답했다: 스테이블코인 = 허브 권위, 그 외 코인/토큰(BANA 포함) = BANA DB 권위.

이에 따라 `docs/specs/staking-yield-system-v2-prd.md`(개정 01)의 다음 절이 갱신 대상이 된다.

| 절 | 갱신 사유 |
|----|-----------|
| §2 사실표 | N-14~N-20 신규 (BANA = `ManagedCoin`, 온체인 BEP-20, 카탈로그 층에서 이미 분할되어 있음) |
| §2.1.1 (B-0) | (A)/(B) 이분법이 틀렸다. 모델 (C) 분할 권위로 재판정. 4개 반론 재채점 |
| §4.4 / §9 G-0″ | B-1′(허브 크레딧 API)가 스테이킹 범위에서 소멸(moot). B-1″(온체인 출금 이행)로 대체 |
| §13 차단표 | B-1′ 강등, B-2-i 의미 반전, B-2-ii 종결, B-7/B-8 신설 |
| §13.1 질의서 | 4문항 중 1번 강등·2번 반전·3번 사실상 해소 → 파트너 질의보다 마스터 확인이 선행 |
| §15 비목표 | "커스터디 모델 변경" 경계 재정의 |

## 왜

- 코드에 이미 코인별 분할의 절반이 존재한다(`ManagedCoin` 카탈로그, 그랜트 경로의 BANA 예외,
  출금 정책의 STABLECOINS 분기). 없는 것은 **로컬 잔고 원장** 한 층뿐이다.
- 따라서 마스터의 답변은 신규 아키텍처 제안이라기보다 **미완성 설계의 완성 지시**에 가깝다.
  단, 그 한 층이 실제 온체인 토큰에 대한 커스터디 청구권을 만든다.
- 개정 01의 (B) 반론 4개 중 2개는 소멸하고 1개는 축소되며 1개는 **확정 결함**이 된다.
  이 재채점 없이 진행하면 게이트가 실제보다 무겁거나 가볍게 보인다.
